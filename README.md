# 小小鵺

Windows 上的 OneBot 群聊机器人与本机控制面板。当前版本 **1.8.1**。

支持人设编辑、短句与表情、上下文和调用额度控制、多个群并行运行、天网管理、群专属插件、可恢复卸载、回复文案编辑，以及按每次机器人发言前后各10条消息提炼的群专属学习日志。模型服务使用兼容 Chat Completions 的 HTTPS API。

## 回复链路诊断（v1.8.1）

“本群运行与诊断”显示最近1/6/24/72/168小时的接收、处理、生成、确认发送与不回复原因；旧日志未记录的阶段明确显示“未记录”，不能据此推算回复率。错误日志读取有限的轮转历史，按安全错误码提供中文建议，不回显供应商原始响应或聊天内容。

模型连接测试使用固定短文本，并共享请求排队、并发与额度保护，30秒内限制重复测试；测试结果保存时间，5分钟后标为旧结果。模型列表可读不代表实际生成可用。长段收集、排队、生成与发送等待分别计入有效期，默认回复有效期改为120秒。@成功率、冷却、消息和调用上限仍按用户保存的各群参数。

本机与托管面板需要同时管理时，运行 `Open-Local-ControlCenter.cmd` 使用本机5102/5103入口，原托管SSH入口仍为5100/5101。也可设置 `NUEBOT_PANEL_PROFILE=local` 后运行原启动器。两个面板使用不同登录cookie，避免互相退出登录；本机SnowLuma仍只连接本机5099，不混用托管端。

## 统一控制室（v1.7.0）

双击 `Open-ControlCenter.cmd`，或运行 `start-panel.ps1`，进入 `http://127.0.0.1:5100/`。主管理员可以在同一网页切换原有全部鵺设置与“QQ / SnowLuma”控制台，托管账号继续使用运行维护页。启动入口只启动面板，不启动机器人、QQ 或 SnowLuma 注入功能。

SnowLuma 需要先在机器人所在机器安装并启动，其 WebUI 保持监听 `127.0.0.1:5099`。控制室只连接运行机器的该固定地址，保留 SnowLuma 自己的登录和验证流程。桥接入口使用本机 `127.0.0.1:5101`，与鵺主页面分属不同浏览器源；所有页面、资源和接口均要求有效的鵺主管理员会话。保留 SnowLuma 的头像、配置、上传和实时状态流；当前适配依据为 SnowLuma 1.14.19。桥接不改动 SnowLuma 文件，也不代理 OneBot WebSocket 端口。

远程管理时，在已有 SSH 命令中同时转发这两个本机入口，目标均为托管机器的同一个面板端口：

```powershell
ssh -N -L 127.0.0.1:5100:127.0.0.1:5100 -L 127.0.0.1:5101:127.0.0.1:5100 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 托管用户名@托管TailscaleIP
```

两个本机端口应空闲，SSH 主机指纹仍需按原方式核对。托管端无需为 SSH 增加新的目的端口权限，也不需要开放公网监听；SnowLuma 访问由托管端面板转接。管理电脑的 5099 不会被当作托管端控制台。两边先升级到同一版本，安装包合并覆盖程序文件并保留私有账号、设置、密钥、素材与学习数据。

## 本机部署

需要 Python 3.11 或更新版本，以及你自行安装、配置并登录的 QQ/OneBot 接入端。本仓库不附带 QQ、SnowLuma、第三方运行时、插件图片或任何账号信息，也不自动注入或安装 QQ 插件。

在程序目录中执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe setup_local.py
```

初始化只创建缺少的本地文件，不覆盖已有配置。填写本机 `model.json` 的API地址、模型与密钥，确认 `account.json` 中的机器人、主人、默认群号和 OneBot 配置路径正确，然后运行 `start-panel.ps1`。

面板地址：`http://127.0.0.1:5100/`。首次配置完成后，在面板选择参与群，再启动机器人。默认不开启天网处罚、插件或记忆学习；开启某群学习前应确认该群消息可送往你选用的模型服务。机器人只使用配置的主人账号接收停机指令。

## 从已有小小鵺迁移

首次迁移需要私下复制你自己的配置和资源，并运行 `setup_local.py` 补充账号文件。各电脑独立保存 `account.json`、`model.json`、`settings.json`、`persona.txt`、`moderation.json`、表情资源、插件素材和学习日志；这些内容禁止提交到公开仓库。公开程序包不包含媒体资源，抽签、塔罗、食物、原曲和符卡数据需从你自己的旧部署迁移。

机器人主体更新时先停止所有群后台并退出面板服务，备份程序和本地数据，再将新包的程序文件复制到原目录。发布包不会包含上面的私有文件；不要删除这些本地数据。启动面板核对版本后，由你决定恢复机器人。

## 自动检查更新

在“07 备份与工具”填写发布仓库 `main` 分支下 `latest.json` 的原始内容地址：

`https://raw.githubusercontent.com/YanagawaHsk/nuebot/main/latest.json`

v1.1.2 起，如果原始文件域名访问超时，可以改用 GitHub 官方 API 地址：

`https://api.github.com/repos/YanagawaHsk/nuebot/contents/latest.json`

也可使用相同清单的公开镜像：

`https://cdn.jsdelivr.net/gh/YanagawaHsk/nuebot@main/latest.json`

镜像有缓存，新发布的版本可能延迟显示；能直接访问 GitHub 时优先使用原始地址。

两端填写同一地址。默认每6小时检查一次，也可立即检查；显示新版本和下载地址。当前功能检查和提示更新，不自动安装，不同步你的密钥、人设、群配置、账号登录状态或学习日志。

## 发布新版本

修改 `version.json` 的版本号和发布日期，以及 `CHANGELOG.md`。提交到自己的仓库后，推送与版本号相同的标签，例如 `v1.1.2`。

GitHub Actions 会用文件白名单生成 Windows 源码包，计算 SHA256，发布 Release，再更新 `main` 分支的 `latest.json`。包中的版本必须与标签一致。未来新增程序文件时同步修改 `tools/build_release.py` 的白名单。

首次发布可在工作流中选择手动运行，输入当前标签；这会发布或补全同名 Release。更新清单只在程序包上传成功后更新。

## 管理与边界

面板保持只监听本机。远程管理需要另外设置可信的私有隧道；不要直接把此面板开放到公网。运行主机的管理员仍可修改程序或读取本地密钥，主人指令不构成对主机管理员的技术隔离。

本仓库包含程序适配层，不发布第三方插件图片、用户表情或私聊、群聊记录。首次迁移资源请自行确认其使用范围。


## 登录与托管权限（v1.2.0）

启动面板后首先显示登录页。首次启动会在程序目录生成 `admin-setup-code.txt`；主管理员读取此文件，填写初始化码、自己的账号和至少12个字符的密码。初始化完成后入口关闭、码文件删除。不要让托管人员先创建主管理员。

主管理员进入“10 账号与权限”，创建托管账号，并私下向托管人员提供该账号的初始密码。账号独立于QQ号；QQ主人指令仍由 `account.json` 的 `owner_id` 识别。

| 权限 | 主管理员 | 托管人员 |
| --- | --- | --- |
| 查看运行状态、运行事件、版本 | 允许 | 允许 |
| 启动、停止、重启机器人 | 允许 | 允许 |
| 修改人设、群、API、记忆、天网、插件 | 允许 | 禁止 |
| 管理账号、查看操作审计 | 允许 | 禁止 |
| 修改本人密码 | 允许 | 允许 |

主管理员账号不可删除、禁用或被托管人员重置。禁用、删除或重置托管账号密码会立即使其旧登录失效。密码使用随机盐和scrypt校验值保存；登录有效期8小时，退出、重启面板或修改密码后需重新登录。失败登录有频率限制，后台对每条管理接口检查角色与会话，并保留最近1000条不含密码的操作审计。

首次迁移时可以私下复制 `panel-accounts.json`，保留原主管理员和托管账号；**不要放到公开仓库，也不要复制尚未使用的初始化码**。审计文件 `access-audit.jsonl` 同样只保留本机。程序更新不会覆盖这些文件。

忘记主管理员密码时，先退出面板服务，在可信运行主机执行 `.\.venv\Scripts\python.exe manage_access.py reset-admin`，按照本机提示恢复密码。恢复操作会记录审计，原登录会失效。

远程访问仍通过私有网络和SSH隧道；普通浏览器连接另一台电脑不会自动成为管理连接。当前账号是每个运行实例各自维护的账号，没有中央账号同步服务。迁移时由你建立或迁移主管理员，给托管人员单独账号。应用权限无法阻止拥有运行主机Windows管理员权限的人改程序、读取文件或停机。


## AI安全防护（v1.3.0）

主管理员在“11 AI安全防护”调整群消息注入过滤、学习记忆防投毒、提示词泄露检查，以及疑似攻击时保持安静或简短回应。可增补安全提示词；默认三项过滤开启、疑似攻击保持安静。设置适用于所有参与群，保存后自动加载。核心模块改变时需重启现有机器人进程才能加载新代码。

固定核心提示词保护身份、配置来源和权限边界，聊天中的系统/开发者角色标签、管理员自称、紧急授权、索要密钥及执行请求均作为不可信数据。主人指令仍依据真实QQ账号与固定格式执行，模型无法调用面板、读取文件或修改账号。

学习记忆不会拼进系统提示词；它只是普通参考数据，自动提炼和旧记录应用前均过滤越权条目。模型回复、固定回应和插件文字发送前检查已知密钥、CQ指令、较长提示词原文及常见编码。即使关闭可调过滤，已知密钥与CQ指令检查、身份验证、操作白名单和角色权限始终保留。

面板可本地试用当前规则，查看按群统计和拦截事件；试用不请求模型或发送群消息。事件记录拦截类别，不记攻击原文。过滤可能漏检或误判，不能保证绝对防护，也不自动警告或禁言群友。天网继续遵循既定群规。关闭某项过滤不等于开放后台执行能力。


## 多群接入面板（v1.4.0）

主管理员进入“群总览”，输入群号添加配置，或读取机器人已加入群并选择添加。新增配置默认不参与、不启用插件和学习。勾选“参与对话”后保存并应用，再启动机器人；已运行时保存参与群的变更会重启现有后台以应用。机器人必须已经加入所选群，程序不会自行申请加入新群。

列表集中显示参与草稿、每群后台状态、插件启用数量和学习开关，提供跳转到该群插件和学习页面的按钮。最多保存20条参与群设置，同时运行已启用的群。上下文、聊天频率、输出上限、话题和表情额度、临时安静、警告计数、插件状态和学习日志按群隔离；人设、关系、关键词、天网规则、模型与可选总额度保护共用。默认显示群不限制并行参与其他群。

## 群工作区（v1.5.0）

顶部“当前群”同时选择聊天节奏、上下文与回复上限、学习日志、插件及运行诊断的对象。切换群保留各群草稿，点击“保存并应用”统一保存。主导航分为群工作区、全局角色与规则、系统管理，原有人设、天网、关键词、关系、API、账号、AI防护、插件卸载恢复与文案编辑、备份和更新功能均保留。

`runtime_groups` 按群保存完整聊天设置；`runtime` 仅作为新群默认节奏。旧版配置首次读取时将原节奏复制到各个已有群，保存后彼此独立；已有学习和插件配置原样保留，新群学习与插件默认关闭。

`account_limits` 是另外一层所有群总额度保护。迁移时默认开启并保留旧的消息和模型调用总上限；可在群总览中调整或关闭。开启时，发送及模型调用须同时满足本群额度和总额度；关闭后仍严格执行各群自己的上限。全局计数与各群计数在同一文件锁中结算，重启不会清空已保存额度。插件图片、表情、警告也算消息。

临时安静只影响所选群，群内主人指令也只作用于所在群。旧版全群安静时间在尚未单独设置过的群中继续生效，可逐群结束。停止机器人仍停止所有群。

更新前备份本地数据、停止群后台并退出旧面板服务，再复制程序并重新启动。无需重填模型密钥或重新创建面板账号，但面板服务重启会使原会话失效，需要重新登录。内存中的聊天上下文与尚未完成的学习采样需重新积累，已保存学习日志和插件素材不受影响。

## 收集、排队与发送保险（v1.6.0）

“02 记忆与节奏”按群调整等待设置。建议最后一条消息后停顿12秒；逗号、冒号或“然后/因为”等未完句等20秒；长段收集45秒后有至少8秒停顿才开始准备，发送前仍检查12秒停顿与后续补充。长段收集是软上限，不在持续输入时强行插话。生成后的自然暂停沿用每群原有设置。默认回复有效期90秒；排队、生成和等待都占用有效期，过期草稿不会补发。

优先根据QQ引用消息区分话题，“换个话题”等明确转折或120秒时间间隔建立新话题；默认只参考该话题最近300秒内的上下文，条目数量仍受本群设置限制。自动话题划分可能识别不了所有语义转折；引用消息最能明确接话对象。发送文字回复时附带QQ引用目标。多个群的历史、等待批次、发送记录和学习日志互不混用。

“API与接入”新增所有群共用的模型调度设置，建议并发1、请求开始间隔2秒、排队25秒、请求30秒。被@优先，其次群聊和天网，再到主动话题和记忆提炼。同一服务遇到429或临时服务错误时统一退避；服务返回的Retry-After等待会优先遵守。请求读取有超时和大小限制，状态更新独立运行。队列不会解决服务余额、额度不足或无效密钥，错误日志能区分这些问题。

“错误与重发”显示当前群最近日志、分类、错误码及建议，不显示密钥或供应商响应原文。发送记录存于本机delivery-queue.sqlite，最多200条带内容任务、50MiB压缩内容；终结记录保留最近1000条。仅重试已生成并通过发送检查的文字、表情和插件回复；天网警告、禁言不自动重试。

默认自动重试开启，最多3次实际发送，失败后按5秒、10秒等递增等待；发送前失败的自动领取也有次数上限。每次检查原群、话题版本、有效期、安静模式、插件状态和额度。下一段必须等待上一段确认成功；有一段被归档或过期，后续段也停止补发。重启后，发送中断的任务转为待核实。

超时和缺少回执不能证明未发送，因此待核实记录绝不自动补发，并停止机器人发送以防重复。主管理员先核验QQ；近期记录中没有匹配项也不能证明没发出。人工确认后可选择“确认已发送”或“确认未发送并放弃”；仍在有效期内的明确未发消息才可重发。托管人员没有这些私有内容和管理接口权限。等待补发不保证最终一定送达。

学习提炼仍以一次确认发送前后各10条消息为样本，额外请求在共用队列低优先级运行。临时网络/限流失败保留相同样本，最多5次尝试；长期授权错误、格式错误或不安全输出仅记录失败，不自动应用。旧失败日志未保存原始样本，不能凭空重新提炼。学习开关关闭会作废排队及在途结果；进程重启会丢失尚未保存的采样，已保存日志保持不变。
